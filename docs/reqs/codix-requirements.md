# Codix 需求规格

## 1. 定位

Codix 是跑在终端里的 agent 工作台，引擎是 Agix。它是 Agix 的参考宿主，把 Agix 独有的能力摆到用户面前：

- 一个进程跑多个会话
- 无人值守
- 子 Agent 与任务看得见、管得着
- 按流程执行长线任务
- 定时作业

Codix 不跟 Claude Code、Codex、opencode 拼"聊天写代码"的打磨。对话区是入口，右栏才是差异。

**目标用户**：在本机或服务器上让 agent 长时间干活、需要随时查看和介入的人。场景不限于编程，运维、调研、写作、数据处理都在内。

## 2. 术语

| 词 | 含义 | 来自 |
|---|---|---|
| 会话 / 主 Agent | 用户直接对话的那个 agent，一个会话对应一个主 Agent | Agix 会话 |
| 子 Agent | 主 Agent 派出去的 agent。有自己的侧链会话，可以再派子 Agent | Agix `Agent` 工具，任务 `kind: agent` |
| 任务 | 在会话之外继续跑的工作：子 Agent、团队成员、Shell 命令、监视器、程序（RunCode）、MCP 任务、会话内的定时任务 | Agix `session.tasks` |
| goal | 会话目标：一轮做不完，引擎自动开下一轮，直到完成、受阻或轮数用完 | Agix `session.goal` |
| todo | 主 Agent 自己维护的待办清单 | Agix `TodoWrite` 工具 |
| 流程 | 一份定义：由**站**组成的有向无环图，每站有工作和出口条件。格式与 Harnix 兼容 | Harnix flow |
| 运行 | 一个流程在一个主题上的一次执行，也就是流程的实例 | Harnix flow |
| 站 | 流程里判断的单位：做什么（skill + 执行者），怎么才算过（输出契约、门禁、人确认） | Harnix flow |
| 作业 | 定时触发的工作。分两种：**简单作业**（提示词 + skills，跑一轮对话）和**流程作业**（启动一次流程运行） | Codix |
| 场景 | Agix 的 scene，决定工具、提示词、是否有人值守。Codix 不绑定某一个场景 | Agix scene |

## 3. 使用场景

| 编号 | 场景 |
|---|---|
| S1 | 在本机项目目录里打开 `codix`，和 agent 对话完成一件事，看着它派子 Agent、跑命令，中途批准或插话 |
| S2 | ssh 到服务器上打开 `codix`，让它排查日志；派出去的几个子 Agent 在右栏一目了然，挑一个点进去看它在做什么 |
| S3 | 服务器上常驻 `codix serve`，本地用 `codix --connect` 连过去。断线不影响工作，重连后自动追平 |
| S4 | 在对话里设计一个流程（比如"需求 → 设计 → 实现 → 评审"），试运行，确认后保存；之后对不同的主题启动多次运行，每一站都可以检视、确认、返工 |
| S5 | 定义作业：每天 9 点跑一次巡检（简单作业）；每周一对上周的工单跑一遍"分类 → 汇总 → 待确认"流程（流程作业）。打开 Codix 就能看到历史，并点进去看每一次的结果 |
| S6 | 好几个会话、运行、作业都在等人（审批、确认、受阻），一个键依次跳过去处理 |

## 4. 功能需求

优先级：

- **P0**：阶段 2（mock）必须做完并验收。
- **P1**：阶段 2 做出界面，接缝后再完善。
- **P2**：以后再做。

### 4.1 布局（L）

| 编号 | 需求 | 优先级 |
|---|---|---|
| L-01 | 左边是对话区，右边是标签栏：会话 / 流程 / 作业 | P0 |
| L-02 | 宽屏（≥ 120 列）左右并排，可以调整两边的宽度比例；窄屏时只显示一栏，用一个键在两栏之间切换 | P0 |
| L-03 | 右栏可以整体收起，只留对话区 | P0 |
| L-04 | 标签头上显示"等你处理"的数量（审批、确认、受阻、失败） | P0 |
| L-05 | 一个键跳到下一处等你处理的地方，可以跨会话、运行、作业（S6） | P0 |

### 4.2 对话区（C）

对话区显示的是一个**上下文**，可能是：某个主 Agent 的会话、某个子 Agent 的侧链会话、某次流程运行的主会话、某个流程的编写会话。顶栏显示面包屑，Esc 返回上一层。

| 编号 | 需求 | 优先级 |
|---|---|---|
| C-01 | 流式显示回答正文与思考过程，思考过程可以折叠 | P0 |
| C-02 | 工具调用画成块，结果超过阈值时自动折叠，可以选中块来展开或收起；文件修改显示 diff | P0 |
| C-03 | 模型某一步失败被重发时，丢掉这一步已经画出来的文字 | P0 |
| C-04 | 权限审批：允许一次、本会话总是允许、拒绝（可以写理由）。多个审批排成队列，可以在它们之间切换 | P0 |
| C-05 | 模型提问：选项题可以用上下键或数字键选，也可以自由输入；引擎撤回提问（超时、被取消）时，对话框随之消失 | P0 |
| C-06 | 中断正在跑的这一轮 | P0 |
| C-07 | 运行中继续输入：缺省是插话（steer），在下一个步骤边界进入对话；没赶上被退回的消息要放回输入框 | P0 |
| C-08 | 输入框：多行、历史、按词按行编辑、粘贴 | P0 |
| C-09 | slash 命令补全：本地命令 + 引擎为这个会话提供的命令表 | P0 |
| C-10 | 状态行：这一轮在做什么、耗时、token；压缩时显示"压缩中" | P0 |
| C-11 | 转录区可以滚动，有新内容时提示，一键回到底部跟随 | P0 |
| C-12 | 切换模型（`/model`），下一轮起生效，以引擎的确认为准 | P1 |
| C-13 | 侧问 `/btw`：不打断当前轮、不污染主对话，在分叉出来的会话上问一句 | P1 |
| C-14 | 通知：模型主动提醒、引擎提醒，显示在底栏，有时效 | P1 |
| C-15 | 子 Agent 的上下文里，输入的内容通过"给任务发消息"送到这个子 Agent；只读的上下文（已经结束的任务）禁用输入框 | P0 |

### 4.3 会话标签（S）

右栏分成上下两段。

| 编号 | 需求 | 优先级 |
|---|---|---|
| S-01 | **上半是主 Agent（会话）列表**。每行显示名字、状态、所属项目或场景、token。可以按项目过滤 | P0 |
| S-02 | 展开一个主 Agent，显示它的 **goal**（目标、阶段、轮次、受阻原因）和 **todo**（完成数 / 总数，以及每一项） | P0 |
| S-03 | goal 的操作：设定、暂停、恢复、修改、清除 | P1 |
| S-04 | **下半是选中主 Agent 的拆分树**：主 Agent → 子 Agent（可以递归）→ 任务。每个节点显示类型、状态、耗时、token，"在等人"的节点要高亮 | P0 |
| S-05 | 在树上选中一个子 Agent，按 Enter，对话区切到它的侧链会话；选中一个 Shell 或监视器任务，看它的输出（实时跟随） | P0 |
| S-06 | 任务的操作：停止、发消息 | P0 |
| S-07 | 新建会话：选项目、场景、模型 | P0 |
| S-08 | 打开历史会话（恢复）、重命名、关闭 | P0 |
| S-09 | 已经结束的子 Agent 和任务默认收起，可以展开 | P1 |

### 4.4 流程标签（F）

同样是上下两段：上半是流程定义（展开后是它的运行），下半是选中运行的各站。

| 编号 | 需求 | 优先级 |
|---|---|---|
| F-01 | 列出流程定义：名字、标题、来源（内置 / 覆盖 / 用户）、运行中的数量 | P0 |
| F-02 | 展开一个流程，列出它的运行：主题、状态（运行中 / 等待 / 暂停中 / 已暂停 / 已完成 / 已取消）、当前站、耗时、token | P0 |
| F-03 | 选中一个运行：下半显示各站。站的状态有待进入、搁置、进行中、未达标、已通过、已跳过、待重做；每站列出它的任务、耗时、token。并行的站用缩进表示，不画图 | P0 |
| F-04 | 选中一个运行时，对话区就是这次运行的主会话，可以插话；站里的子 Agent 和独立会话也能点进去看 | P0 |
| F-05 | 运行的操作：确认、放行（搁置的站）、强制放行（要写理由）、返工（选退回到哪一站）、重试失败的任务、暂停、恢复、取消。不可逆的操作要二次确认 | P0 |
| F-06 | 启动一次运行：选流程，填主题和输入参数 | P0 |
| F-07 | 选中一个流程定义时，对话区是它的**编写会话**：在对话里让 agent 设计或修改流程、校验、试运行、保存。保存要人批准 | P0（界面）/ P1（真实编写） |
| F-08 | 查看流程定义：站的列表与关系、每站的 skill、出口条件；可以看原始 YAML | P1 |
| F-09 | 流程格式与 Harnix 兼容，同一份流程包在两边都能跑 | P1 |

### 4.5 作业标签（J）

上半是作业列表，下半是选中作业的触发历史。

| 编号 | 需求 | 优先级 |
|---|---|---|
| J-01 | 列出作业：名字、触发规则（cron）、类型（简单 / 流程）、是否启用、下次触发时间、上次结果 | P0 |
| J-02 | 选中一个作业，下半列出它的触发历史：时间、结果、耗时、token。按 Enter 跳到那一次的会话（简单作业）或运行（流程作业） | P0 |
| J-03 | 新建或编辑作业。简单作业：提示词 + skills + 项目 / 场景 / 模型。流程作业：流程 + 主题 + 输入参数。复杂任务建议用流程作业来做 | P0 |
| J-04 | 启用 / 停用、立即运行一次、删除（要二次确认） | P0 |
| J-05 | 作业由常驻的宿主执行（本地模式下是 Codix 进程，远程模式下是 `codix serve`）。宿主不在时错过的触发，按作业配置决定是补跑还是跳过 | P1 |

### 4.6 连接与远程（R）

| 编号 | 需求 | 优先级 |
|---|---|---|
| R-01 | 缺省是本地模式：引擎和宿主都跑在 Codix 进程里 | P1 |
| R-02 | `codix serve`：在服务器上常驻宿主（引擎 + 流程 + 作业），交给 systemd / launchd 管理 | P1 |
| R-03 | `codix --connect <地址>`：连接远端的 `codix serve`。地址可以是 unix socket（配合 ssh 转发）或 WebSocket（带 token） | P1 |
| R-04 | 断线不影响远端的工作。界面显示连接状态，自动重连，重连后追平 | P0（界面）/ P1（真实） |
| R-05 | 只想连一个普通的 `agixd`（没有流程和作业）也可以，这时流程和作业标签显示"不可用" | P2 |

### 4.7 配置与诊断（D）

| 编号 | 需求 | 优先级 |
|---|---|---|
| D-01 | `/doctor`：显示实际生效的 provider、模型、数据目录、权限模式、沙箱，以及引擎自检的结果 | P1 |
| D-02 | 用户可以覆盖快捷键，有冲突时启动就报出来 | P1 |
| D-03 | 一键打开帮助：当前焦点下可用的所有快捷键 | P0 |

## 5. 非功能需求

| 编号 | 需求 |
|---|---|
| N-01 | 80 × 24 的终端可用（单栏模式），120 列以上并排 |
| N-02 | 流式输出的开销与转录长度无关：一个 token 只重算它所在的那个块 |
| N-03 | 任何 IO（列会话、读历史、读任务输出）都不阻塞界面，按键随时有响应 |
| N-04 | CJK、emoji、制表符按显示宽度正确排版 |
| N-05 | 阶段 2 的全部交互不需要网络、API key 或 Agix，mock 场景完全确定，可以重放 |
| N-06 | 常见终端可用：iTerm2、Terminal.app、kitty / WezTerm、Linux 控制台、tmux 里、ssh 上 |
| N-07 | 不支持某些键（如 Shift+Enter）的终端，每个动作都有替代键 |

## 6. 不做

- ACP（作为需求提给了 Agix：openatta/Agix#74，Codix 本身不做）
- Web 界面
- Vim 模式、鼠标操作（P2 再议）
- 在终端里显示图片
- 在 Codix 里改 Agix 或 Harnix 的代码：缺什么就到对应仓库提 issue

## 7. 依赖与缺口

| 需要 | 现状 | 处理 |
|---|---|---|
| todo 列表 | Agix 没有专门的方法或事件，只能从 `TodoWrite` 工具调用的入参里取 | 接缝时先从事件里取；不够用再给 Agix 提 issue |
| 流程 | 不在 Agix 里，在 Harnix 的 flow 里 | 拷贝到 `3rds/harnix-flow`，等 Harnix#66 拆分完成 |
| 作业 | Agix 的 `schedule.*` 只能定时跑一轮对话，启动不了流程 | 作业由 Codix 宿主调度 |
| 侧问 | Agix 有 `session.fork` | C-13 接缝时用它 |
